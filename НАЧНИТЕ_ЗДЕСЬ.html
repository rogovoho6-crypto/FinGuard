FinGuard · Docker с нуля

Готовый проект для запуска и дальнейшей разработки.

FINGUARD В DOCKER — ИНСТРУКЦИЯ С НУЛЯ

1. ЧТО УЖЕ УСТАНОВЛЕНО

Docker Desktop работает, Ubuntu и docker-desktop используют WSL 2.
Повторно устанавливать WSL или Docker не нужно. Для этого проекта достаточно
Windows: команды ниже вводятся в PowerShell, а не в терминале Ubuntu.
Не нужно отдельно устанавливать Python, Node.js или Docker внутрь Ubuntu.

Docker Desktop — программа, которая запускает контейнеры.
Образ (image) — собранное приложение с зависимостями.
Контейнер (container) — работающий экземпляр образа.
Том (volume) — отдельное хранилище базы; переживает замену контейнера.
Compose — описание того, какие контейнеры запускать вместе.

2. САМЫЙ ПРОСТОЙ ЗАПУСК

Откройте Docker Desktop ярлыком на рабочем столе. Дождитесь работающего Engine.
В папке FinGuard_DOCKER дважды нажмите 01_start.bat.
Дождитесь окончания сборки. Браузер откроет http://localhost:8765.
Логин: finguard. Пароль хранится в файле .env в этой же папке:
откройте .env Блокнотом и скопируйте только значение после FINGUARD_PASSWORD=.
Если файла нет, 00_prepare.bat автоматически создаст случайный пароль.
Не отправляйте .env вместе с исходниками.

В первый запуск нужна сеть для загрузки образов и пакетов. Потом обычный
повторный запуск использует скачанные образы и кэш. Изменение зависимостей
может снова потребовать интернета. Docker Desktop должен оставаться запущенным.

01_start.bat — обычная собранная версия, http://localhost:8765.
02_develop.bat — режим разработки, http://localhost:5173, без пароля.
03_stop.bat — остановить оба режима, сохранив базы.
04_logs.bat — показать последние сообщения и ошибки.
05_test.bat — собрать тестовый образ и выполнить 89 тестов.

Окно bat после запуска можно закрыть: контейнеры работают в фоне.
Закрытие вкладки браузера тоже не останавливает контейнеры.
После перезагрузки компьютера откройте Docker Desktop и нужный bat ещё раз.

3. КАК ПОЛЬЗОВАТЬСЯ DOCKER DESKTOP

Containers — список запущенных приложений. Группа finguard — обычная версия;
finguard-dev — разработка. Внутри группы видны сервисы.
Logs — журнал выбранного контейнера; полезен, если страница не открывается.
Images — собранные образы. Новые функции появляются после сборки нового образа.
Volumes — базы данных. Не удаляйте тома приложения, если данные нужны.
Остановка контейнера не равна удалению базы.

4. РАЗРАБОТКА: ПЕРВАЯ ПРОВЕРЯЕМАЯ ПРАВКА

Запустите 02_develop.bat и откройте http://localhost:5173.
В редакторе (например, VS Code) откройте всю папку FinGuard_DOCKER.
Откройте frontend/src/pages/Overview.tsx. Измените заголовок
«Финансовая безопасность», сохраните Ctrl+S и посмотрите браузер.
Vite автоматически обновляет экран после сохранения; в отдельных случаях
состояние формы может сброситься. Не редактируйте node_modules или файлы образа.

Frontend/src — экраны и элементы интерфейса React/TypeScript.
Backend/app.py — HTTP API и проверка запросов.
Backend/service.py — сценарии приложения.
Backend/core — финансовые правила и SQLite. Изменения ядра проверяйте тестами.
Изменения Python автоматически перезапускают сервер. Подождите несколько секунд;
если операция попала на перезапуск, повторите её после обновления страницы.

Режим разработки использует отдельную базу. Данные, введённые на порту 5173,
не появятся сами на 8765. Для переноса используйте резервную копию в интерфейсе.
Порт 8766 — прямой доступ к API разработки; для обычной работы открывайте 5173.
Все опубликованные порты привязаны только к этому компьютеру (127.0.0.1).

После изменения обычного .tsx/.py-файла не нужна пересборка dev-контейнера.
После изменения requirements, package.json, lockfile или Dockerfile заново
запустите 02_develop.bat. Затем проверьте 05_test.bat.
Чтобы правка появилась в обычной версии, запустите 01_start.bat: production
использует собранные файлы, а не подключённую папку исходников.

5. КОМАНДЫ В POWERSHELL (ЕСЛИ ХОТИТЕ РАБОТАТЬ ВРУЧНУЮ)

Откройте PowerShell. Перейдите в папку проекта:
cd "$env:USERPROFILE\Desktop\FinGuard_DOCKER"

Обычная версия:
.\00_prepare.bat
docker compose up --build -d --wait
docker compose ps
docker compose logs --tail 80
docker compose stop

Разработка:
docker compose -f compose.dev.yaml up --build -d --wait
docker compose -f compose.dev.yaml logs --tail 80
docker compose -f compose.dev.yaml stop

Тесты:
docker compose -f compose.test.yaml build
docker compose -f compose.test.yaml run --rm tests

В конце тестов должно быть: Ran 89 tests ... OK.
Ключ -d означает «работать в фоне», --build — «проверить необходимость сборки»,
--wait — «дождаться готовности сервисов». Для logs -f используйте Ctrl+C,
чтобы выйти из просмотра журнала: контейнеры продолжат работать.

6. ДАННЫЕ, ОБНОВЛЕНИЯ И РЕЗЕРВНЫЕ КОПИИ

Обычная база хранится в томе finguard_finguard-data.
База разработки — finguard-dev_dev-data. В контейнерах каталог базы /data.
Файлы проекта и базы — разные вещи: копирование папки не переносит Docker-том.
Перед обновлением откройте «Проверка командой», создайте копию и скачайте её.
На другом компьютере установите Docker Desktop, распакуйте архив проекта,
запустите 01_start.bat и загрузите скачанную SQLite-копию через интерфейс.
Создастся новый пароль для нового компьютера.

Для штатной остановки пользуйтесь 03_stop.bat. Не используйте down -v,
docker volume rm или очистку Docker Desktop с удалением volumes:
эти действия могут удалить базу. Обычная пересборка и stop сохраняют данные.
Не запускайте две копии папки с одним Compose-именем как независимые базы:
имена finguard и finguard-dev намеренно постоянны.

7. ЕСЛИ ЧТО-ТО НЕ РАБОТАЕТ

«Cannot connect to Docker daemon» / ошибка pipe: откройте Docker Desktop,
дождитесь Engine running и повторите запуск. Для этого не надо переустанавливать Ubuntu.
«Port is already allocated»: закройте ранее запущенный FinGuard-Web.exe либо
остановите другую копию приложения на портах 8765, 8766 или 5173.
«docker не распознано»: перезапустите PowerShell после установки Docker Desktop.
Ошибка скачивания образа/пакета: проверьте сеть и повторите bat. Базы не удаляйте.
Неверный пароль: откройте .env и проверьте значение. После изменения пароля
запустите 01_start.bat и заново откройте браузер/приватное окно.
Изменения кода не видны: проверьте, что открыто 5173 и редактируется именно
папка на рабочем столе. 8765 обновляется через сборку 01_start.bat.
Если ошибка остаётся: откройте 04_logs.bat и сохраните сообщение об ошибке.
Не отправляйте файл .env или вывод docker compose config: там может быть пароль.

8. ЧТО ЭТОТ ПАКЕТ НЕ ДЕЛАЕТ

Он запускает FinGuard на вашем компьютере. Общедоступный сайт и домен
автоматически не создаются. Учётные записи отдельных сотрудников и роли
пока не реализованы: обычная версия — одна общая рабочая область.
Исходная desktop-версия и предыдущий веб-проект сохранены отдельно.

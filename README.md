# FinGuard

Веб-приложение для проверки платёжного реестра и прогноза денежных средств малого бизнеса.
Показывает возможные повторные платежи и ошибки реквизитов, сохраняет решения пользователя
и сравнивает сценарии переноса или исключения нескольких платежей из прогноза.

## Жюри — запуск и демонстрация

**[Пошаговая инструкция для жюри](docs/JURY.md)** — установка, вход, демонстрация и решение проблем.

1. Установите и запустите **Docker Desktop** с Linux-контейнерами и Docker Compose v2.
   На Windows Docker Desktop использует WSL 2. Python, Node.js и Git для просмотра не нужны.
2. Нажмите **Code → Download ZIP** или [скачайте исходники](https://github.com/rogovoho6-crypto/FinGuard/archive/refs/heads/main.zip).
   Полностью распакуйте архив и откройте папку с `compose.yaml`.
3. На Windows дважды нажмите **`01_start.bat`** и дождитесь завершения сборки.
   Для macOS и Linux команды приведены [в инструкции](docs/JURY.md#macos-и-linux).
4. Откройте **http://localhost:8765**. Логин — **`finguard`**, пароль — значение
   `FINGUARD_PASSWORD` в локальном файле **`.env`**, созданном при первом запуске.
5. В разделе **«Проверка командой»** загрузите набор **«Повторный платёж»** и перейдите в **«Обзор»**.

Первому запуску нужен интернет для загрузки образов и зависимостей; время зависит от соединения.
После сборки приложение работает локально. Репозиторий общедоступный, аккаунт GitHub для скачивания не нужен.
Ссылка на репозиторий открывает исходники и инструкцию; приложение запускается на компьютере проверяющего.

## Что показать за пять минут

- Из карточки **«Возможные дубли»** откройте операцию №2 и причины сигнала, сравните с №1.
- Измените ручное решение: оно влияет на список рисков, а не на денежный остаток.
- В **«Симуляторе»** исключите №2, перенесите №3 на 7 дней, №5 на 40 дней; горизонт 30 дней,
  общие изменения поступлений и дополнительный расход — 0.
- Конечный остаток: **282 000 → 480 000 ₽**, разница **+198 000 ₽**;
  **48 000 ₽** обязательств остаются за горизонтом. Это синтетический пример, не предотвращённый убыток.
- Сохраните сценарий и откройте сравнение. В **«Проверке командой»** запустите самодиагностику.

## Проверки и разработка

| Файл | Действие |
| --- | --- |
| `01_start.bat` | Собрать и запустить обычный режим на http://localhost:8765 |
| `02_develop.bat` | Разработка с автообновлением на http://localhost:5173 |
| `03_stop.bat` | Остановить оба режима, сохранив данные |
| `04_logs.bat` | Показать сообщения сервисов |
| `05_test.bat` | Собрать тестовый образ и выполнить 89 тестов |

Команды для тестов на любой платформе:

```sh
docker compose -f compose.test.yaml build
docker compose -f compose.test.yaml run --rm tests
```

Стек: React, TypeScript, FastAPI, Python, SQLite, Docker. Финансовые расчёты выполняются на сервере.
В production используется один процесс; данные находятся в именованном Docker-томе.
Базы обычного режима и разработки разделены. Все опубликованные порты ограничены локальным компьютером.

FinGuard не подключается к банку и не выполняет переводы. Сигнал о дубле требует ручной проверки,
а исключение из сценария не отменяет обязательство. Текущая версия рассчитана на одну рабочую область;
отдельных аккаунтов, ролей и изоляции нескольких организаций нет.

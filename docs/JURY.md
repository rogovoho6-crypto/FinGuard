# FinGuard — инструкция для жюри

## Что вы проверяете

FinGuard помогает проверить реестр до оплаты и оценить кассовый разрыв. В приложении есть
объяснения возможных дублей и ошибок реквизитов, ручные решения, прогноз на 30 / 60 / 90 дней,
сценарии из нескольких платежей, импорт CSV с предпросмотром и резервные копии.
Демонстрационные данные синтетические; подключение к банку не требуется.

## Что понадобится

- Компьютер с установленным **Docker Desktop**: [официальная установка](https://docs.docker.com/desktop/).
  На Linux также подходит Docker Engine с плагином Docker Compose v2.
- На Windows включён WSL 2 и в Docker Desktop используется Linux engine.
  Если после установки требуется перезагрузка, выполните её до запуска проекта.
- Свободный порт **8765**, браузер и интернет на время первой сборки.
  Учётная запись GitHub, Python, Node.js и редактор кода для проверки не нужны.

Проверка готовности Docker в терминале: `docker info` и `docker compose version`.
Обе команды должны завершиться успешно. На Windows все команды можно выполнять в PowerShell;
открывать Ubuntu отдельно не нужно.

## Скачать проект без аккаунта

1. Откройте [репозиторий FinGuard](https://github.com/rogovoho6-crypto/FinGuard).
2. Нажмите **Code → Download ZIP**. [Прямая ссылка на ZIP](https://github.com/rogovoho6-crypto/FinGuard/archive/refs/heads/main.zip).
3. Полностью распакуйте архив. Не запускайте файлы из окна ZIP.
4. Откройте извлечённую папку **FinGuard-main**, в которой лежат `compose.yaml` и `01_start.bat`.

Разработчики могут вместо ZIP выполнить `git clone https://github.com/rogovoho6-crypto/FinGuard.git`.

## Windows

1. Запустите Docker Desktop и дождитесь состояния работающего engine.
2. В папке проекта дважды нажмите **`01_start.bat`**.
3. Скрипт создаст локальный `.env` со случайным паролем, соберёт контейнер и дождётся готовности.
   При повторном запуске существующий пароль и данные сохраняются.
4. После сборки откроется браузер. Если этого не произошло, откройте **http://localhost:8765**.
5. В окне входа укажите пользователя **`finguard`**. Откройте `.env` Блокнотом
   и скопируйте только значение после `FINGUARD_PASSWORD=`, без имени параметра.

Файл `.env` начинается с точки и может быть скрыт проводником; включите показ скрытых элементов
или в PowerShell из папки проекта выполните `notepad .env`. Это пароль только вашей локальной установки;
в репозитории общего пароля нет.

Если запускать из PowerShell вручную:

```powershell
.\00_prepare.bat
docker compose up --build -d --wait
```

## macOS и Linux

В терминале перейдите в распакованную папку проекта. Скопируйте шаблон настроек:

```sh
cp .env.example .env
```

Откройте `.env` любым текстовым редактором и задайте собственный пароль минимум из 12 символов
после `FINGUARD_PASSWORD=`. Используйте латинские буквы и цифры без пробелов; остальные настройки
оставьте как в шаблоне. Этот шаг нужен только при первом запуске. Затем выполните:

```sh
docker compose up --build -d --wait
```

Откройте **http://localhost:8765**, пользователь **`finguard`**, пароль — введённое значение.

## Демонстрация за пять минут

1. Откройте **«Проверка командой»**, выберите набор **«Повторный платёж»** и подтвердите загрузку.
   При замене текущих данных автоматически создаётся копия. Начальный демонстрационный остаток — 300 000 ₽.
2. В **«Обзоре»** нажмите **«Возможные дубли»**. Откроется список с кандидатом №2 на 150 000 ₽.
   Нажмите операцию, изучите причины и сравнение с №1.
3. Поставьте решение **«Не дубль»**: активный сигнал исчезнет, денежный прогноз останется прежним.
   Верните **«Ожидает ручной проверки»** для продолжения показа.
4. В **«Симуляторе»** добавьте три действия: №2 исключить из прогноза; №3 перенести на 7 дней;
   №5 перенести на 40 дней. Горизонт — **30 дней**, снижение и задержка поступлений,
   дополнительный расход — **0**. Нажмите **«Рассчитать сценарий»**.
5. Ожидается **282 000 → 480 000 ₽** на конец горизонта, разница **+198 000 ₽**.
   **48 000 ₽** перенесены за горизонт; обязательство сохраняется. Сценарий не изменяет исходный реестр.
6. Введите имя сценария, сохраните его, загрузите снова и откройте сравнение.
7. В **«Проверке командой»** запустите самодиагностику: должны пройти **9 проверок**.
   Здесь же можно скачать пример CSV, открыть предпросмотр импорта и отменить его, не заменяя данные.

Эти суммы относятся к указанному набору и параметрам. При своих данных или иных датах результаты
могут отличаться. Сумма кандидатов на дубли не является доказанной финансовой потерей.

## Автоматическая проверка

На Windows запустите **`05_test.bat`**. На любой платформе из папки проекта:

```sh
docker compose -f compose.test.yaml build
docker compose -f compose.test.yaml run --rm tests
```

Ожидаемый итог: **`Ran 89 tests`** и **`OK`**. Тесты используют временные базы и не меняют реестр
запущенного приложения. Сборка также проверяет TypeScript и собирает браузерный интерфейс.

## Остановить и запустить снова

```sh
docker compose stop
docker compose up -d --wait
```

На Windows `03_stop.bat` останавливает также режим разработки. Реестр и сохранённые сценарии
остаются в Docker-томе. Не применяйте `docker compose down -v`, если хотите сохранить данные:
параметр `-v` удаляет том базы. После изменения исходников запускайте `docker compose up --build -d --wait`.

## Если что-то не запустилось

| Сообщение или ситуация | Что сделать |
| --- | --- |
| `Cannot connect to the Docker daemon` / engine не готов | Открыть Docker Desktop, дождаться запуска и повторить команду |
| `port is already allocated` | Остановить ранее запущенную копию FinGuard или другое приложение на 8765 |
| Повторно появляется окно входа | Пользователь `finguard`; пароль из `.env` именно этой папки; без `FINGUARD_PASSWORD=` |
| `Set FINGUARD_PASSWORD` / пароль короче 12 символов | На Windows запустить `00_prepare.bat`, если `.env` ещё нет; иначе проверить файл вручную |
| Ошибка загрузки образа или зависимости | Проверить интернет и доступ Docker к registry, затем повторить сборку |
| Браузер не открылся автоматически | Ввести `http://localhost:8765` вручную; проверить `docker compose ps` |
| После обновления виден старый интерфейс | Пересобрать контейнер с `--build` и обновить страницу с Ctrl+F5 |

Для диагностики из папки проекта:

```sh
docker compose ps
docker compose logs --tail=100
```

Не публикуйте `.env`, финансовые реестры или базы вместе с сообщением об ошибке.
Для проверки нужен один экземпляр приложения: копии с одинаковым именем Compose-проекта
используют общие контейнеры и тома.

## Границы первого спринта

Это локальная установка одной рабочей области. Она не выполняет платежи, не подтверждает владельца счёта
и не заменяет проверку бухгалтера. Прогноз зависит от реестра, ожидаемых дат и сверенного остатка.
Публичный GitHub даёт доступ к исходникам; постоянно работающий сайт в интернете в этот выпуск не входит.

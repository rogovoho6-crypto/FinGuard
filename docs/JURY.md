# FinGuard — инструкция для жюри

Эта инструкция поможет запустить приложение и проверить основные функции на демонстрационных данных.
Для знакомства с продуктом достаточно пройти раздел «Проверка основных функций».

## Что понадобится

- **Docker Desktop** и браузер. Установщик: [официальный сайт Docker](https://docs.docker.com/desktop/).
  На Windows Docker Desktop должен работать с WSL 2 и Linux-контейнерами.
  После установки выполните перезагрузку, если её запросит установщик.
- Интернет для первой сборки: Docker загрузит компоненты приложения.
  Время ожидания зависит от соединения; дождитесь завершения, не закрывая окно запуска.
- Свободный порт **8765**. Запускайте одну копию FinGuard на компьютере.

Для проверки продукта устанавливать Python, Node.js и Git не требуется. Вход в GitHub не нужен.
На Linux вместо Docker Desktop можно использовать Docker Engine с Docker Compose v2.

## Скачать приложение

1. [Скачайте ZIP проекта](https://github.com/rogovoho6-crypto/FinGuard/archive/refs/heads/main.zip)
   или на [странице репозитория](https://github.com/rogovoho6-crypto/FinGuard) нажмите **Code → Download ZIP**.
2. Нажмите правой кнопкой по архиву и выберите **«Извлечь всё»** либо распакуйте его привычным способом.
   Запускать файлы прямо из окна архива не нужно.
3. Откройте распакованную папку **FinGuard-main**. В ней должны лежать `01_start.bat` и `compose.yaml`.

Ссылка GitHub открывает проект и инструкцию. Сам FinGuard запускается на компьютере проверяющего.

## Запуск на Windows

1. Откройте **Docker Desktop** и дождитесь состояния **Engine running**.
2. В папке **FinGuard-main** дважды нажмите **`01_start.bat`**.
3. Дождитесь окончания сборки. Скрипт сам создаст настройки и случайный пароль, затем запустит приложение.
   Если в конце появилось сообщение об ошибке, обратитесь к разделу «Если приложение не открылось» ниже.
4. Откроется браузер с адресом **http://localhost:8765**. Если вкладка не появилась, введите адрес вручную.
5. В окне входа укажите:
   - **Имя пользователя:** `finguard`.
   - **Пароль:** откройте файл `.env` из той же папки Блокнотом и скопируйте значение после `FINGUARD_PASSWORD=`.
     Само `FINGUARD_PASSWORD=` и перевод строки копировать не нужно.

Пароль создаётся отдельно для вашей установки. Если `.env` не виден, включите показ скрытых элементов
в Проводнике. Можно также открыть PowerShell в папке проекта и выполнить `notepad .env`.

После успешного запуска окно скрипта можно закрыть. Docker Desktop должен продолжать работать.

## Запуск на macOS и Linux

1. Запустите Docker Desktop либо Docker Engine с Docker Compose v2.
2. Откройте терминал в распакованной папке **FinGuard-main**, где лежит `compose.yaml`.
3. При первом запуске скопируйте шаблон настроек:

```sh
cp .env.example .env
```

Если `.env` уже существует, используйте его, повторно копировать шаблон не нужно.
Откройте `.env` текстовым редактором и впишите после `FINGUARD_PASSWORD=` собственный пароль
из 12 или более латинских букв и цифр без пробелов. Сохраните файл; остальные строки оставьте как есть.

4. Запустите приложение:

```sh
docker compose up --build -d --wait
```

5. Откройте **http://localhost:8765**. Имя пользователя — **`finguard`**, пароль — введённое значение из `.env`.

## Проверка основных функций

### 1 Подготовить демонстрационные данные

Откройте раздел **«Проверка командой»**. В карточке **«Повторный платёж»** нажмите **«Загрузить набор»**,
затем подтвердите действие кнопкой **«Загрузить набор»** в появившемся окне.
Это сбросит демонстрационный пример к исходному состоянию на текущую дату.

Начальные значения: **9 операций**, фактический остаток **300 000 ₽**, **3 операции требуют внимания**.
Повторная загрузка заменяет текущий реестр и остаток; перед этим автоматически создаётся резервная копия.
Для проверки используйте предложенный пример, загружать реальные финансовые данные не требуется.

### 2 Разобрать возможный повторный платёж

1. Перейдите в **«Обзор»** и нажмите карточку **«Возможные дубли»**.
2. В открывшемся списке выберите **№2 · ООО Альфа** на **150 000 ₽**.
   В карточке операции видны реквизиты и объяснение сигнала. Кнопка **«Сравнить с №1»** откроет связанную операцию.
3. Вернитесь к **№2**. В поле **«Решение по возможному дублю»** выберите **«Не дубль»**.
   Активный сигнал по этой паре исчезнет, сумма операции и прогноз не изменятся.
4. Чтобы продолжить пример с исходным состоянием, откройте фильтр **«Все операции»**, снова выберите №2
   и верните **«Ожидает ручной проверки»**.

### 3 Рассчитать изменения нескольких платежей

Откройте **«Симулятор»**. Если в нём уже есть настройки, нажмите **«Очистить текущий сценарий»**.
В блоке **«Параметры сценария»** последовательно заполните поля и каждый раз нажмите **«Добавить действие»**:

| Платёж | Действие с платежом | Перенести на дней |
| --- | --- | --- |
| №2 · ООО Альфа | Исключить из прогноза | Поле не используется и недоступно |
| №3 · Аренда офиса | Перенести платёж | 7 |
| №5 · Поставщик Бета | Перенести платёж | 40 |

В списке **«Действия в сценарии»** должны появиться **три платежа**. Затем задайте:

- **«Горизонт прогноза»** — **30 дней**.
- **«Снижение доходов, %»** — **0**.
- **«Задержка доходов, дн.»** — **0**.
- **«Дополнительный расход на 10-й день, ₽»** — **0**.

Нажмите **«Рассчитать сценарий»**. В результате должны отображаться:

| Показатель | Ожидаемое значение |
| --- | --- |
| Остаток на 30-й день по текущему плану | 282 000 ₽ |
| Остаток на 30-й день по сценарию | 480 000 ₽ |
| Изменение остатка | +198 000 ₽ |
| Выплаты после горизонта | 48 000 ₽ |
| Учтено платежей | 3 |

Расчёт меняет только сценарий. Перенос №5 оставляет обязательство на 48 000 ₽ после горизонта;
увеличение остатка не означает, что весь прирост является экономией.
Ожидаемые суммы относятся к заново загруженному набору и параметрам из этой инструкции.

### 4 Сохранить и повторно открыть результат

В блоке **«Сохранить и сравнить»** введите в поле **«Название сценария»** имя, например **«Проверка жюри»**,
и нажмите **«Сохранить сценарий»**. Затем нажмите **«Очистить текущий сценарий»**, выберите сохранённый
вариант в поле **«Сохранённый сценарий»** и нажмите **«Загрузить»**. Все три действия должны восстановиться.

Кнопка **«Сравнить сохранённые»** открывает таблицу результатов. Для сравнения двух вариантов сохраните
ещё один сценарий под другим именем с другими параметрами. **«Скачать расчёт»** сохраняет результат в JSON.

### 5 Проверить импорт и самодиагностику

В разделе **«Проверка командой»** скачайте **«Пример CSV»**. Нажмите **«Импорт CSV»** в верхней части экрана
и выберите скачанный файл. Приложение покажет предпросмотр изменений. Нажмите **«Отмена»**,
чтобы сохранить текущий пример. Импорт применяется только после подтверждения **«Заменить реестр»**.

В блоке **«Самодиагностика»** нажмите **«Запустить проверку»**: должны появиться **9 результатов OK**.
Проверка использует временные данные и не меняет текущий реестр.

## Работа со своим реестром

Этот раздел необязателен для оценки демонстрации.

1. Подготовьте CSV по структуре скачанного **«Примера CSV»** и загрузите его через **«Импорт CSV»**.
   Проверьте предпросмотр перед подтверждением замены.
2. В **«Обзоре»** укажите **фактический остаток** и **дату остатка**, нажмите **«Сохранить остаток»**.
   В сумме уже должны быть учтены исполненные операции. При старой дате расчёт отмечается как предварительный.
3. В **«Платежах»** открывайте операции, проверяйте причины сигналов и сохраняйте ручные решения.
   После изменения статуса исполнения повторно сверьте фактический остаток.
4. В **«Симуляторе»** задавайте переносы и исключения, сравнивайте минимум остатка, дни дефицита
   и обязательства после горизонта. При изменении параметров нажимайте **«Рассчитать сценарий»** или **«Пересчитать»**.
5. Для копии данных откройте **«Проверка командой» → «Резервные копии» → «Создать копию»**.
   Скачайте её кнопкой со стрелкой вниз возле имени файла. **«Отчёт JSON»** выгружает данные и расчёты.

FinGuard не выполняет банковские переводы. Сигналы требуют ручной проверки, а прогноз зависит от полноты
реестра и актуальности остатка. Программа в этом выпуске работает с одной рабочей областью на вашем компьютере.

## Завершить проверку и открыть снова

На Windows запустите **`03_stop.bat`**. Для следующего запуска откройте Docker Desktop и снова нажмите **`01_start.bat`**.
Пароль, реестр и сохранённые сценарии сохранятся. Закрытие вкладки браузера само по себе не останавливает приложение.

На macOS и Linux из папки проекта:

```sh
docker compose stop
```

Повторный запуск:

```sh
docker compose up -d --wait
```

Не удаляйте хранилище приложения в Docker Desktop, если хотите сохранить результаты проверки.

## Если приложение не открылось

| Ситуация | Что сделать |
| --- | --- |
| Docker не запущен / `Cannot connect to the Docker daemon` | Открыть Docker Desktop, дождаться Engine running и повторить запуск |
| Первая сборка долго загружает файлы | Оставить окно открытым; проверить интернет, если появилась ошибка загрузки |
| Порт занят / `port is already allocated` | Остановить ранее запущенную копию FinGuard или другое приложение на порту 8765 |
| Вкладка не появилась | Открыть http://localhost:8765 вручную |
| Окно входа появляется повторно | Проверить имя `finguard` и пароль из `.env` именно этой распакованной папки |
| Нет `.env` / `Set FINGUARD_PASSWORD` | На Windows запустить `00_prepare.bat`, затем `01_start.bat`; на macOS и Linux выполнить шаги настройки выше |
| Показано сообщение о коротком пароле | В `.env` должен быть пароль длиной не менее 12 символов; после исправления повторить запуск |
| Появилось сообщение об ошибке запуска | Сохранить текст ошибки; на Windows журнал доступен через `04_logs.bat` |

Если нужна диагностика на macOS и Linux, из папки проекта выполните:

```sh
docker compose ps
docker compose logs --tail=100
```

При передаче сообщения об ошибке не прикладывайте `.env` или собственные финансовые данные.
